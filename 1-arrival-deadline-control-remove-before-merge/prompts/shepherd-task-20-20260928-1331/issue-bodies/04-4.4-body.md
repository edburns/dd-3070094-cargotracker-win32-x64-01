## Resolved decisions and research findings

- Mirror the existing Change Destination dynamic-dialog lifecycle: the editor remains CDI `@Named @ViewScoped`, while the launcher is a serializable JSF managed bean named `changeArrivalDeadlineDateDialog` with `@SessionScoped`.
- Open `/admin/dialogs/changeArrivalDeadlineDate.xhtml` with one `trackingId` parameter in `Map<String, List<String>>`.
- Required options are: `modal=true`, `draggable=true`, `resizable=false`, `contentWidth=410`, and `contentHeight=280`.
- Successful editor submission closes with `"DONE"`; cancellation closes with the empty string and must not invoke the facade. The caller's eventual `dialogReturn` handling updates `tableNotRouted`.
- Because the prepared Open Liberty runtime uses MyFaces, `<f:metadata>` must be a direct child of the root `<html>` element before `<h:head>` and `<h:body>`. Nesting it in `<h:body>` causes the known `UIViewRoot`/parent-component failure.
- The date picker requires a non-null value with normal Faces validation feedback, but no new chronological business rule.
- Runtime verification—not modernization of the remote-Payara Arquillian setup—is the mandatory executable evidence for this UI task.

## Implement

Create:

- `src/main/java/org/eclipse/cargotracker/interfaces/booking/web/ChangeArrivalDeadlineDateDialog.java`
- `src/main/webapp/admin/dialogs/changeArrivalDeadlineDate.xhtml`

The launcher must be serializable and use:

```java
@ManagedBean(name = "changeArrivalDeadlineDateDialog")
@SessionScoped
```

Implement `showDialog(String trackingId)`, `handleReturn(SelectEvent event)`, and `cancel()`. Follow the existing destination dialog's repository-compatible PrimeFaces APIs and lifecycle. `showDialog(...)` supplies the exact options and request parameter above. `cancel()` closes with an empty string and performs no facade call.

The XHTML title must be `Change Deadline`. Place this metadata directly beneath `<html>` and before `<h:head>`:

```xhtml
<f:metadata>
    <f:viewParam name="trackingId"
                 value="#{changeArrivalDeadlineDate.trackingId}"/>
    <f:viewAction action="#{changeArrivalDeadlineDate.load}"/>
</f:metadata>
```

The form must show read-only `Origin:` / `changeArrivalDeadlineDate.cargo.originName` and `Destination:` / `changeArrivalDeadlineDate.cargo.finalDestinationName`, plus a labeled, required `p:datePicker` bound to `changeArrivalDeadlineDate.arrivalDeadlineDate`. Add **Cancel** invoking `changeArrivalDeadlineDateDialog.cancel()` and **Update** invoking `changeArrivalDeadlineDate.changeArrivalDeadline()`. Include visible validation feedback and preserve accessibility labels.

The dialog must also work when loaded directly with a `trackingId` query parameter. Do not connect it to the dashboard yet.

## Tests

Run the application on JDK 17 and directly request:

`http://localhost:8080/cargo-tracker/admin/dialogs/changeArrivalDeadlineDate.xhtml?trackingId=DEF789`

Verify:

- HTTP 200 and title **Change Deadline**;
- origin, destination, and current deadline render;
- no `TagException`, `<f:metadata> Parent UIComponent`, `FacesException`, or server error;
- required validation prevents null submission and displays feedback;
- Cancel closes without changing the persisted deadline;
- Update changes the deadline and closes successfully;
- a failed update does not look successful;
- the existing Destination dialog still works.
